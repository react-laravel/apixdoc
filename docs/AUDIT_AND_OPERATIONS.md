# 操作审计与运行保障

## 操作记录

`/dashboard/audit` 汇总成功提交的组织、项目、目录、接口、配置、导入、团队、发布及账号管理变更。业务变更与审计记录在同一数据库事务中提交，记录失败不会留下无审计的成功变更。

索引保留对象 ID、操作类型、操作者名称、对象名称，以及经过白名单筛选的字段名、版本号、数量和角色等元数据。它不复制请求体、配置值、响应示例、密码、邀请密钥或原始规范。接口内容差异仍在接口版本历史中查看。

组织所有者和管理员可查看当前管理组织的记录；平台管理员可跨组织查询。删除项目或组织不会级联删除审计记录，删除后的组织记录仅平台管理员可访问。应用不提供修改审计记录的接口，这不等同于数据库层的防篡改存储。

- `GET /api/audit/scopes`：当前可见范围。
- `GET /api/audit`：筛选 organizationId、projectId、actorId、action、q、from、to；时间为 ISO 时间，界面将所选本地日期转换后提交。
- 每页 50 条，用 next 作为 cursor 继续读取。
- 增加 `format=csv` 导出最多 5000 条；超过时应缩小筛选范围。CSV 转义引号、换行和可能被电子表格当成公式的标签。

这里记录已提交业务变更，尚不覆盖全部读取、登录尝试或失败请求。未知服务器异常以问题编号关联结构化运行日志，日志仅记录时间、类别、异常类型与安全错误码，不输出原始异常消息或请求内容。

## 清理过期记录

维护命令默认只预览 180 天以前的记录，不会自动运行：

```sh
npm run audit:retention
npm run audit:retention -- --days=180 --organization=组织ID
npm run audit:retention -- --days=180 --apply
```

显式提供 `--apply` 才会删除。命令每批最多 500 条，并在同一事务写入清理数量与保留天数。由部署运维身份配置合适的保留周期和执行安排；不要把测试数据库当作生产审计备份。

## 健康检查

- `/api/health/live`：只检查进程能否响应，返回 200。
- `/api/health/ready`：检查数据库连接、迁移完成状态和必要数据表；未就绪返回 503，附 Retry-After: 5。
- 公共探针只返回状态，不暴露数据库地址、环境变量或错误细节。
- 检查合并并发请求并缓存最多 5 秒，设置连接和语句时限，避免探针对故障数据库造成持续压力。
- 平台管理员在 `/dashboard/operations` 查看检查结果、迁移状态、进程信息、对象数量和 APP_REVISION。

服务端未知错误返回问题编号，同时在进程错误日志中写入相同编号。就绪检查失败也会生成编号，平台管理员可据此关联日志。

## 部署与初始化

部署健康检查改用就绪探针，curl 设置连接与整体超时。保留最近 3 个应用版本，并向 PM2 传入当前 Git 提交。部署复制排除开发环境文件、浏览器测试产物及本地工具目录，运行配置只从部署目录显式复制。

部署不再自动运行 seed。首次安装在迁移完成后，通过环境变量提供管理员邮箱和密码，再显式初始化：

```sh
ADMIN_EMAIL='you@example.com' ADMIN_PASSWORD='使用唯一的长密码' npm run db:seed
```

新管理员密码至少 12 位且不超过 bcrypt 的 72 字节限制。初始化没有默认密码，不提升已有普通账号，也不覆盖已有管理员密码。既有账号保持原样。

应用版本保留不能代替数据库备份；迁移不会随应用回滚自动撤销。当前健康检查不构成告警平台，备份恢复演练、配额和完整失败请求审计仍需继续完善。

## 回归命令

`npm run test:audit` 在 localhost/127.0.0.1 开发数据库验证记录覆盖、敏感值排除、范围权限、回滚、分页、删除保留及清理行为，并清理自己的数据。单元测试覆盖元数据白名单、CSV 公式保护、探针去重/缓存、公开健康响应和管理员初始化输入。
